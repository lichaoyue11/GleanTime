开发参考 · 加班记录 v3

1核心用户操作流程添加 / 修改 / 删除 / 筛选

  1. 启动后默认停在「加班记录」页：顶部三张汇总卡展示「累计加班 / 可调休加班 / 折算调休天数」，下方明细列表按加班日期倒序排列。
  2. 点击右下角圆形「＋」按钮，自底部弹出「添加加班记录」弹层。默认值：日期＝今天、起始 18:30、结束 21:30、类型＝可调休、有效时长＝按起止时间自动算得的加班时长。
  3. 依次完成：加班日期（点输入框唤起自绘日历）→ 起止时间（唤起时／分双列滚动下拉）→ 加班原因（选填）→ 加班类型（可调休／攻关／法定节假日）→ 按需修正有效加班时长。
  4. 点击「保存记录」：校验通过 → 追加记录 → 弹层收起 → 列表与三张汇总卡即时重算 → 底部 toast 反馈「已添加 …」。
  5. 修改：列表项向左滑动露出「修改 / 删除」→ 点「修改」 → 弹层切为编辑态（标题「修改加班记录」、按钮「保存修改」）并预填原值 → 保存为原地更新（保留原 id 与已发生的调休抵扣）。
  6. 删除：同一路径点「删除」 → 记录立即移除并刷新列表与汇总 → toast「已删除加班记录」。无二次确认；滑动本身绝不触发删除。
  7. 筛选：点「全部年份 / 全部月份」下拉选择 → 明细列表与顶部汇总同时收敛到该区间，并出现「重置」按钮；点重置回到全部。

2界面元素交互行为点击左侧对应元素可定位

顶部汇总卡 实时重算.summary-row
累计加班＝Σ 命中记录的「有效加班时长」；可调休加班＝Σ 类型为「可调休」的有效时长；折算调休＝可调休时长 ÷ 8（保留 1 位小数，单位「天」）。 三张卡随年-月筛选实时重算，与下方列表口径严格一致；筛选生效时列表上方出现说明行「已按所选时间区间实时统计（命中 N 条加班记录）」。 数值格式统一为最多 2 位小数（如 40.57 / 3.0），单位「h」以更小字号跟随主数值。

加班明细列表 左滑手势#recList
每条记录展示：日期 · 星期、本次加班时长、起止时间区间（跨天显示「次日」）、有效加班时长、加班原因与状态标签；可调休记录额外标注剩余可抵扣时长与有效期截止日。 左滑：横向拖动时卡片跟随手指左移，最多露出 152px（两个 76px 动作按钮）。进入滑动态的判定为「水平位移 > 6px 且大于垂直位移」；松手时位移 ≥76px 保持展开，否则回弹收起。 点击已展开的卡片即收起；滑动结束后 400ms 内屏蔽浏览器补发的 click，避免「一滑就删」。 同一时刻只允许展开一行：滑开新行会收起其他行；切换页签、打开弹层同样收起全部行。 拖拽过程中容器随露出状态切换底色，保证卡片圆角处不出现异色渗边。
「修改」按钮 蓝色 · 左位.swipe-action.edit
仅当该行已滑出（容器带 .is-open）时点击才生效；未滑出时点击无效——滑动只负责露出按钮，不承载任何业务动作。 点击后打开添加弹层并切换为编辑态：标题「修改加班记录」、副标题「修改加班信息，时长将根据起止时间自动计算」、主按钮「保存修改」，且表单预填该记录的日期 / 起止时间 / 原因 / 类型 / 有效时长。
「删除」按钮 红色 · 右位.swipe-action.del
同样要求该行已滑出；点击后直接删除（无二次确认），移除该 id 的记录并持久化、刷新全部页面与统计。 删除一条已有调休抵扣的可调休记录时，其 deductions 一并移除：相应调休事件在「调休记录」页同步消失或金额减少，「可用」额度随之回涨。

圆形主色按钮，固定于右下角、位于底部导航之上。本页点击＝添加加班（打开添加弹层）；在「调休记录」页点击＝使用调休（打开抵扣弹层）；在「时长统计」页自动隐藏。 纯图标按钮、无内联文字，仅通过 title 提供悬浮提示（添加加班 / 使用调休）。

5异常与边界情况

  • 跨天加班：结束时间 ≤ 起始时间时按次日计算（22:00 → 02:00 ＝ 4h）。弹层出现「跨天」角标与提示行，列表时间区间显示为「22:00 — 次日 02:00」。
  • 有效时长大于本次时长：保存时自动截断为本次加班时长，保证「有效 ≤ 本次」。
  • 编辑时有效时长小于已抵扣：自动上调至已抵扣值并 toast，避免产生「负剩余」。
  • 起止时间缺失：保存前拦截并 toast，弹层不关闭、已填内容保留。
  • 无任何记录：列表显示空态「暂无加班记录 / 点击右下角「＋」添加加班」，计数留空。
  • 筛选无命中：显示「该年月暂无加班记录 / 试试切换其他年份或月份」，计数显示「共 0 条（全部 N 条）」。
  • 删除后 id 不回收：新增记录取「现有最大 id ＋ 1」，已删除的 id 不复用，避免与历史备份做导入合并时冲突。
  • 原因留空：落库为「未填写原因」而非空串，列表渲染始终有文案。
  • 超长/特殊字符原因：渲染前统一做 HTML 转义，防止破坏列表结构。
  • 数据持久化：每次增删改后写入 localStorage["overtime_records_v3"]；存储不可用时静默降级，不影响本次会话内的操作。
  • 滑动与点击互斥：水平位移不足 6px 视为点击；滑动结束后 400ms 内屏蔽 click，防止误删。
  • 垂直滚动优先：垂直位移大于水平位移时不进入滑动态，列表正常滚动。

1核心用户操作流程区间统计 / 导出 / 导入

  1. 点底部导航切到「时长统计」：标题变为「时长统计」、内容区滚动位置归零、右下角FAB 自动隐藏（本页无新增类操作）。
  2. 默认区间为「全部」，环形图与时长概览均按全量数据计算。
  3. 点「去年」/「今年」 → 立即按整年区间重算（去年 01-01 ~ 12-31 / 今年 01-01 ~ 12-31），并给出「统计范围：… · 命中 N 条加班记录」。
  4. 点「时间」 → 展开自定义起止日期行；分别点击开始、结束输入框唤起日历。两个日期都选定后才按该区间统计，仅填一端不生效（此时显示「请选择开始与结束日期，两者都选定后即按该区间统计」）。
  5. 查看「调休额度构成」环形图（可用 / 已使用 / 已过期）与「时长概览」分项，两者均收敛到所选区间。
  6. 数据导出：点「数据导出」→ 弹层显示文件名与「N 条记录 · 体积」→ 选择保存到本地 / 发送给微信好友 / 复制为文本。
  7. 数据导入：点「数据导入」→ 选择从本地文件选择 / 从微信聊天文件选择 → 按 id 合并去重导入 → toast 汇总「新增 / 覆盖 / 跳过」条数。

5异常与边界情况

  • 起止日期倒置：若先选结束、后选更晚的开始，系统自动交换两端，保证区间始终有效，而不是变成空区间。
  • 只填一端：不施加过滤，统计保持原值，仅提示补全；避免出现「区间半成品」导致的误读。
  • 「清除」按钮：只清空两个日期、不改变模式，清空后回到提示态而非「全部」。
  • 切走页面再回来：统计区间与自定义日期在会话内保留（不随切页重置）。
  • 导入空文件：toast「文件内容为空」，不修改任何数据。
  • 导入非 JSON 文本：解析失败即拦截，不进入合并流程，数据保持原样。
  • 导入缺少 records 数组：拦截并提示格式不正确；同时兼容纯数组格式的备份文件。
  • 导入脏记录：缺 id / date / start / end 的记录被跳过并计数，在 toast 里单独说明，绝不写入内存——避免污染统计与列表渲染。
  • 导入重复执行（幂等）：同一文件重复导入不会产生重复数据，同 id 记录始终只保留一份（后导入覆盖先导入）。
  • 文件类型限制：本地导入只接受 .json（扩展名或 MIME 命中其一即可），其他类型直接提示并中止。
  • 重复选择同一文件：选择器在读取后清空 value，同一文件可再次选中并重新导入。
  • 下载失败降级：环境不支持 Blob 下载时自动改为复制到剪贴板；复制再失败则进入手动复制步骤③，不存在「无路可走」的死路。
  • 零记录导出：无任何记录时仍可正常导出（records 为空数组），便于「清空后备份」场景。
  • 真机环境差异：浏览器下无 wx 对象时，微信相关入口使用演示数据；检测到 wx.chooseMessageFile 时自动切换为真实小程序 API。

1核心用户操作流程使用 / 修改 / 撤销 / 筛选

  1. 点底部导航切到「调休记录」：标题变为「调休记录」，右下角 FAB 的语义切换为「使用调休」。
  2. 顶部三张卡展示可用 / 已使用 / 已过期，为全局口径（不随本页年-月筛选变化），与「时长统计」页全量口径一致。
  3. 点右下角「＋」 → 自底部弹出「使用调休」弹层。
  4. 依次完成：选择调休使用日期（默认今天，点击输入框唤起日历）→ 在「可调休且仍有剩余、未过期」的加班清单中勾选要抵扣的项 → 按需修改每项的抵扣时长（上限＝该笔剩余）→ 核对底部「本次抵扣 / 抵扣后可用」→ 点「确认抵扣」。
  5. 修改：列表项向左滑动露出「修改 / 撤销」→ 点「修改」 → 弹层进入编辑态（标题「修改调休记录」、按钮「保存修改」），预填该笔调休在各加班上的原抵扣 → 保存语义＝先撤销原事件、再按新选择重算（天然支持改日期、改抵扣来源、改时长）。
  6. 撤销：同一路径点「撤销」 → 删除该调休日期的全部抵扣 → 相关加班的剩余额度回涨 → 列表与统计刷新 → toast「已撤销 …」。
  7. 筛选：按调休使用日期的年 / 月过滤下方列表；顶部三张汇总卡不受筛选影响。

5异常与边界情况

  • 无可用额度：清单区显示空态文案，勾选与保存均无从进行；用户可先到「加班记录」页确认是否还有未过期、未用完的可调休加班。
  • 抵扣时长超过该笔剩余：输入即被实时钳制到上限，不允许录入超额值；保存时再做一次钳制兜底。
  • 抵扣后可用为负：底部「抵扣后可用」卡片转为警示样式，提示已超出可用总额。
  • 未勾选任何项就保存：拦截并 toast，弹层保持打开；编辑态下也不会破坏原记录（校验先于撤销执行，避免出现「原数据已撤销但新值未写入」的中间态）。
  • 同一日期重复使用调休：同一天再次提交会追加为该日期的额外抵扣来源，列表仍聚合成一条、时长累加。
  • 编辑时改到其他日期：语义是「撤销旧日期的这一笔 + 在新日期重新写入」，旧日期若无其他来源则从列表消失。
  • 编辑时移除某个原来源：该加班被释放的时长立即回到可用额度，可在同一次操作中抵扣到别的加班上。
  • 有效期边界：有效期含截止日当天；截止日当天仍可抵扣，次日起该笔剩余归入「已过期」且不再出现在可勾选清单中。
  • 非「可调休」类型：攻关、法定节假日类型的加班永远不进入抵扣清单，也不参与额度构成。
  • 列表筛选不影响额度：年-月筛选只影响列表展示，顶部「可用 / 已使用 / 已过期」始终为全局口径。
  • 撤销不可恢复：无二次确认、无撤销栈；如需找回请重新进入弹层按原来源与时长重新抵扣。
  • 与加班记录联动：在「加班记录」页删除一条含抵扣的记录，本页对应调休事件同步减少或消失，额度实时回涨。
